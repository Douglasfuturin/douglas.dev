# Slide Pattern Catalog

> The visual vocabulary of the 150-slide deck. Each pattern is a named slide type with a specific structure, used at predetermined moments in the composite framework. The render script (`scripts/render_deck.py`) maps these pattern names to HTML templates in `templates/slide-types/`.

## How to use this catalog

When generating the deck spec (markdown intermediate), each slide is tagged with a pattern name. Example:

```yaml
- slide: 22
  pattern: big-claim
  text: "Real estate is the only vehicle that compounds tax-free."
```

The render script reads the pattern name and applies the corresponding HTML/CSS template.

## Pattern reference

### `title`
The opening slide, it carries the webinar **title, the promise, and the meta** all in one (the promise is NOT a separate slide). Webinar titles can be long; the title font is `--title-size` and wraps gracefully to 2-3 lines.
```
[Webinar Title]              <- title-size, can be long, wraps
[The promise, "how to X without Y"]   <- body-size, supports <accent>
[meta_main · meta_accent · meta_secondary]   <- small, muted
```
Content fields: `title`, `promise_html` (or `promise`), `meta_main`, `meta_accent`, `meta_secondary`.

### `big-text`
Single line of large text, centered. Hero promise, key claim, framework name.
```
[1-12 word statement]        <- 120-180pt
```

### `mono-word`
A single word, full screen. Pattern breaks. "Listen.", "Wait.", "Yes."
```
[Word].                      <- 200pt+
```
Use sparingly, and **vary it per webinar**, a one-word pattern break is a tool, not a fixed slide. Don't ship the identical "Today." beat in every deck. A `mono-line` ("By the end of today, you'll know three things.") often serves the same moment with more substance.

### `mono-line`
A single short line. Transitions like "Here's the thing." or "But here's what's interesting..."
```
[Short line]                 <- 80-100pt
```
**Lead-in lines that continue into the next slide trail off with an ellipsis**, not a period, e.g. "By the end of today, you'll know three things..." The "..." signals "the payoff is on the next slide" and keeps the viewer leaning forward. A line that fully completes a thought keeps its period.

### `mono-name`
The presenter's name in introduction.
```
I'm [Name].                  <- 120pt
```

### `three-lines`
Three short lines, stacked. Used for promises ("By the end you'll know..."), agendas, FAQ headlines.
```
[Line 1]
[Line 2]
[Line 3]
```
Each line 40-60pt. Even vertical spacing.

### `permission`
Asks for explicit audience commitment. Used at slide 5 (cold open) and slide 113 (pre-pitch).
```
[Question, ends with question mark]
                                          <- prompt to react in chat
```
Often accompanied by a hold instruction in speaker notes ("wait for chat replies before advancing").

### `instruction`
Tells the audience to do something physical (grab a pen, open a tab, write something down).
```
[Action verb] [object].
[Why it matters, one short line].
```

### `proof-number`
A single number plus its label. Specific. Defensible.
```
$2.4M                        <- hero number, 200pt+
generated by students in 2024
```

### `proof-stat`
Aggregate stat from across multiple students/clients.
```
89%                          <- hero
of students who completed Module 3
hit their first $10k month
```

### `case-study-headline`
One client's outcome in one line. Used in introductions and proof sections.
```
Lauren went from $0 → $50k MRR
in 6 months
```

### `case-study-detail`
A case study expanded, name, starting point, what they did, result, screenshot.
```
[Photo of person, left side]    [Story, right side]
                                Before: [state]
                                After: [state]
                                Time: [interval]
                                What changed: [1 line]
```

### `photo-full`, DEPRECATED
A full-bleed photo with no text. **Do not use.** An image-only slide is a dead beat, the viewer can't tell what they're looking at or why, and the slide carries zero spoken-word reinforcement. Every slide must carry words. Use `photo-text-overlay` instead (same full-bleed image, with a headline). The pattern remains in the template only for backward compatibility.

### `photo-text-overlay`
A full-bleed background image with a text headline overlaid bottom-left. The background image **always fills the entire slide, edge to edge**, `object-fit: cover` guarantees it; a scrim darkens the bottom-left for text legibility.
```
[Background image, fills the whole slide]
[Text headline, bottom-left]      <- big-size
```

**Background image style, three approved kinds (no light flares, no bokeh):**

1. **Dark paper texture**, dark charcoal crinkled/folded paper, raking light catching creases, near-black with subtle tonal variation, matte and tactile, edge-to-edge texture, no subject.
2. **Dark grid / graph paper**, a near-black surface with a precise fine grid of faint thin light lines (graph paper / blueprint), evenly covering the whole frame, minimal and technical.
3. **Darkened illustrative image**, a real scene that illustrates the slide's content, heavily darkened and low-key, with the visual subject and light **concentrated on the side opposite the text** (text is bottom-left → emphasis goes top-right), the text side falling into deep shadow.

**Rules:**
- The image must read as filling the slide, visible texture or detail edge to edge. Black-heavy flare/bokeh images look like they *don't* fill (the black blends into the slide). Avoid them.
- Darkened-illustrative images: emphasis on the top-right, shadow on the bottom-left where the text sits.
- Always generated via the `brand-image` skill, see its `brand-style.md` background rules.

### `logo-wall`
Grid of client / press logos. 6-12 logos in a 3×4 or 4×3 grid.
```
[Logo] [Logo] [Logo] [Logo]
[Logo] [Logo] [Logo] [Logo]
[Logo] [Logo] [Logo] [Logo]
```

### `agenda`
Three-secret preview. Numbered.
```
1.  [Secret 1 name]
2.  [Secret 2 name]
3.  [Secret 3 name]
```

### `bridge`
A short transitional line. Used at the end of each major section.
```
[Bridge phrase]                 <- 80-100pt
```
See `assets/transition-phrases.md` for proven bridge phrases.

### `big-claim`
The Big Domino slide. A single declarative claim, no qualifier. Hero typography.
```
[Claim, stated as fact]
```
Slide 22 is the most important `big-claim` in the deck. Spend extra time on this one.

### `if-true`
Speculative claim, "If this is true, then..."
```
If that's true,
then [downstream effect].
```

### `vs-belief`
Sets up the opposing belief that the deck will dismantle.
```
Most people believe:
"[the wrong belief]"
```

### `alt-behavior`
Describes what people who hold the alternative belief do.
```
So they spend [time/money]
[doing the wrong thing].
```

### `cost-of-alt`
The cost of believing the alternative. Specific.
```
That costs them
[specific amount/outcome]
per [interval].
```

### `reframe-permission`
"If I could show you X, would you act on it?", sets up the rest of the webinar.
```
If I could show you
[claim]
... would you [action]?
```

### `bridge-to-story`
Transition from claim to origin story.
```
Let me show you
how I figured this out.
```

### `scene-setter`
A date + location to open a story. Pattern break + grounding.
```
2019.
Boise.
```

### `framework-named`
A framework with a name on its own slide. Sets up the explanation.
```
The [Framework Name] Method™
```

### `framework-step`
One step of a multi-step framework. Number + name + one-line description.
```
1.
[Step Name]
[One-line description of what happens]
```

### `framework-diagram`
A visual diagram of a multi-part framework. Boxes + arrows. Often the most visually complex slide in the deck.
```
[Box A] → [Box B] → [Box C]
            ↓
         [Box D]
```

### `misconception`
"Most people think X, but actually Y."
```
Most people think:
[wrong assumption]

But actually:
[correct insight]
```

### `screenshot`
A real screenshot, analytics dashboard, payment confirmation, message thread. Full bleed or with thin caption.
```
[Screenshot fills 80% of slide]
[Caption, 1 line, what this is]
```

### `quote`
A customer / student quote in their own words. With attribution.
```
"[Quote]"
                       , [Name], [Role/Niche]
```

### `why-share`
The real reason the presenter is teaching this. Slightly contrarian.
```
Why I'm teaching this:
[Real reason, specific, slightly edgy]
```

### `avatar`
"This is for [specific avatar]."
```
This is for:
- [Specific trait 1]
- [Specific trait 2]
- [Specific trait 3]
```
Note: this is the ONE place bullets are acceptable, describing the avatar is a list by nature.

### `not-for`
"This is NOT for [specific anti-avatar]."
```
This is NOT for:
- [Anti-trait 1]
- [Anti-trait 2]
- [Anti-trait 3]
```

### `stack-line`
One line of the stack slide. Used in slides 127-133.
```
[Component name]                                $X,XXX
[One-line description]
```

### `stack-total`
The total value reveal. Hero typography. Slide 134.
```
TOTAL VALUE:
$XX,XXX
```

### `stack-anchor`
"But you won't pay anywhere close to that..." Slides 135-136.
```
[Anchor adjustment line]
```

### `price-reveal`
The actual price. Slide 137.
```
Today's price:
$X
```

### `offer-mockup`
The visual purchase slide: a product-spread image of the whole offer, with the price beneath it, the anchor price struck through next to the real price. The spread image is generated by the **`product-mockup` skill** (`--type spread`), background removed to a transparent PNG.
```
[Everything you get]              <- small accent tag (optional)
[product-spread image]            <- the offer, visualized as a value stack
[~~$52,000~~  $8,000]              <- struck anchor price + real price (accent)
```
Content fields: `src` (path to the spread cutout PNG), `struck_price`, `price`, `tag` (optional). The struck price is the anchor (the build-it-custom value), not a discount below the real floor.

### `payment-plan`
Payment plan option. Slide 138.
```
or
3 payments of $Y
```

### `comparison-anchor`
Side-by-side comparison with alternatives. Slide 139.
```
vs. agency:        $60,000/yr
vs. doing nothing: 12 more months of $0
vs. this:          $X. Once.
```

### `roi-math`
Explicit ROI calculation. Slide 141.
```
Investment:   $X
First result: $Y
Return:       Z%
```

### `cost-of-not`
Cost of inaction, annualized. Slide 142.
```
Don't do it →
[Specific consequence #1]
[Specific consequence #2]
[Specific consequence #3]
```

### `guarantee-headline`
Risk reversal headline. Slide 143.
```
If you don't [specific result] in [interval],
I'll [specific remedy].
```

### `guarantee-details`
Conditions of the guarantee. Slide 144.
```
Here's how it works:
1. [Condition 1]
2. [Condition 2]
3. [What happens if you don't get the result]
```

### `urgency-reason`
The REAL urgency. Slide 145.
```
Why now:
[Specific reason]
```

### `deadline`
Specific date/time + consequence. Slide 146.
```
Closes [Day, Time, Timezone].
After that: [specific consequence].
```

### `action-plan`
Three steps to take right now. Slide 147.
```
Right now:
1. [Action 1]
2. [Action 2]
3. [Action 3]
```

### `button`
The CTA. URL + a short label. Slide 148 and 150.
```
[CompanyName].com/joinnow
                                <- hero typography for URL
```

### `faq-grid`
Top 5 FAQ on one slide. Slide 149.
```
Q: [Question 1]                  Q: [Question 2]
A: [Answer 1]                     A: [Answer 2]

Q: [Question 3]                  Q: [Question 4]
A: [Answer 3]                     A: [Answer 4]

Q: [Question 5]
A: [Answer 5]
```

### `final-cta`
Final close with URL. Slide 150.
```
[URL]
See you on the other side.
```

## Pattern density across the deck

A healthy 150-slide deck uses ~20-25 different patterns total. Heavy repetition of one pattern = boring. Random pattern variety = chaotic. The composite framework already maps the right pattern to each slide, follow it.

## Animation / transitions

- Default: instant cut
- Permitted: 200ms fade
- NEVER: slide-in, spin, bounce, zoom, dissolve, ripple, any 2010s PowerPoint effect

The render script uses a single CSS transition: `opacity 200ms ease`. That's it.

## Color usage

Default theme:
- Background: `#000000` (true black)
- Primary text: `#FFFFFF`
- Accent color: `#FF5C28` (default, overridable via theme variable)
- Muted text: `rgba(255,255,255,0.6)` for fine print
- Divider lines: `rgba(255,255,255,0.2)`

Accent color is used SPARINGLY, for the key word in a slide, the dollar amount in the stack, the URL in the button slide. Overuse of accent destroys its emphasis function.

## Typography weights

- Hero (mono-word, big-text, big-claim, stack-total, price-reveal): 700 (bold)
- Body (most slides): 500 (medium)
- Fine print (date stamps, attribution, fine print on guarantee): 400 (regular)
- Numbers in proof-number / proof-stat slides: 800 (extra bold)

## Adding new patterns

If a slide doesn't fit any existing pattern, that's a signal, either the slide doesn't belong in the framework, OR the pattern catalog needs a new entry. Don't invent patterns inline in the deck spec. Add to this file first, then use.
