# VSL Skill

Write Video Sales Letter scripts that convert cold paid-ad traffic into qualified appointments, applications, or direct purchases. Output is a teleprompter-ready markdown script following the 11-beat canonical structure, in operator voice (conversational, flowing prose — not staccato), sized for the page type and traffic temperature.

This skill writes the **script the founder reads on camera**, not the video itself. Production (filming, editing, hosting, embedding) is downstream.

## Non-negotiables

1. **Always use the 11-beat structure.** Hook → Promise → Proof up front → Problem agitation → Identity-crisis reframe → Mechanism → How it works → Results stack → Objection handling → Offer + risk reversal → Scarcity + two-paths close. See [references/structure.md](references/structure.md). Skipping beats is a red flag, not a creative choice — every beat earns its place.
2. **Operator voice only.** Conversational, flowing sentences with commas, em-dashes, and "and look," / "here's the thing" / "now look" transitions. No AI-staccato pattern (period-period-period). Oxford commas in lists. See [references/voice.md](references/voice.md).
3. **One specific offer, one specific tribe.** The script is built for ONE audience pitching ONE thing at ONE price point. Multi-product/multi-tier VSLs convert worse than focused ones.
4. **Specific over vague, every time.** "$28 an hour" not "low pay". "$45,000 deal in 60 days" not "great results". Generic numbers ("thousands of customers") are a tell that the writer doesn't know the business.
5. **Length matches traffic temperature.** Cold ad traffic to high-ticket = 10-15 min. Warm traffic to application = 4-7 min. Direct-to-cart tripwire = 3-6 min. See "Length matrix" below.
6. **Stand-alone teleprompter format.** Output is what the founder reads, top to bottom, with timing markers and pause cues but no stage directions inside the spoken lines.

## When to invoke

User says: "write a VSL", "VSL script", "video sales letter", "VSL hook", "opening for my video", "VSL outline", "critique my VSL", "rewrite this VSL", "polish my VSL", "make a 5 minute pitch video", "what should I say in my hero video".

Also infer when: the user has an offer + a landing page + wants to record a hero video for it. VSLs are also used as Facebook/YouTube ad creative (longer-form ads), as webinar replacements, and as podcast episode 0.

## The four workflows

### Workflow A — Draft from scratch

Use when the user has an offer but no script yet.

1. **Intake** — get five things (ask only what you can't infer):
   - **Offer** — what's being sold, what's included, the price (or price range)
   - **Tribe** — exactly who this is for (revenue band, role, pain stage). The narrower the better.
   - **Traffic source** — cold paid ads / warm email / podcast / organic. Affects opener temperature.
   - **CTA goal** — book a call / apply / opt-in / direct purchase / register for event
   - **Target length** — 3-5 min (warm/quick), 7-10 min (cold mid-ticket), 12-15 min (cold high-ticket/challenge)
2. **Outline** — write the 11-beat outline as a markdown table with the headline of each beat and rough word/time budget. Show the user.
3. **Draft** — write the full script in operator voice. Use proven beat formulas from [references/beats.md](references/beats.md).
4. **Self-critique** — before delivering, run the script through the QA checklist below. Flag any beat that's weak.

### Workflow B — Critique an existing VSL

Use when the user pastes a script (or a transcript of a recorded video) and asks for a review.

1. Map the existing script onto the 11 beats — call out which beats are present, missing, or weak.
2. Identify **voice issues** (staccato, AI-tells, missing Oxford commas, throat-clearing openings).
3. Identify **specificity gaps** — places where vague language could be replaced with a real number or named result.
4. Identify **structural drag** — sections that are too long for their conversion lift (most VSLs over-explain the mechanism and under-explain the offer).
5. Output: a beat-by-beat scorecard + a prioritized punch-list of what to change.

### Workflow C — Rewrite / polish

User pastes a draft and asks for a tightened version.

1. Preserve the founder's specific stories, numbers, and named clients — these are gold and unfakeable.
2. Rewrite the connective tissue, transitions, hooks, and pivots in operator voice.
3. Tighten by 20-40% — most first drafts are way over length. Aim for the target time-budget.
4. Output: the rewritten script + a "what changed" summary so the founder can spot anything they want to push back on.

### Workflow D — Beat punch-up

User says "my hook isn't landing" or "the offer reveal is weak — give me 3 versions."

1. Ask which beat. Default to whatever they paste.
2. Produce 3-5 alternates using the formulas in [references/beats.md](references/beats.md). Vary the angle — don't give 5 of the same idea.
3. Note which alternate fits which traffic temperature.

## Length matrix

| Page type | Traffic | Target length | Why |
|-----------|---------|---------------|-----|
| Tripwire / direct-to-cart | Cold ads → checkout | 3-6 min | Visitor only needs to be 80% convinced before $7-$97; short closes faster |
| Application page | Warm/cold → form | 4-7 min | Form does the qualifying; VSL just needs to bait the click |
| Squeeze / webinar reg | Warm → email opt-in | 2-4 min | Visitor is already half-in; brevity wins |
| VSL page (mid-ticket) | Cold ads → call book | 7-10 min | $500-$5k needs more belief-building |
| Challenge funnel | Cold ads → free challenge reg | 10-15 min | The free challenge is a real product; the VSL is selling the challenge as if it were the offer |
| High-ticket VSL | Cold → application/call | 12-18 min | $10k+ requires the full belief stack |

Going long when warm or short when cold are both failure modes — the most common one is going LONG when COLD because the writer over-explains. Trust the matrix.

## QA Checklist (run before delivering any draft)

- [ ] Opens with a hook that names the audience or makes a specific promise within the first 15 seconds. No "Hi everyone, my name is X" openings.
- [ ] Promise + proof land in the first 60 seconds.
- [ ] Problem agitation uses **specific scenarios** (named tools, named amounts, named time-of-day) — not generic pain statements.
- [ ] Mechanism has a name. ("AI Operating System", "The KFC Method", "The Overseer of YouTube" — never just "our process").
- [ ] At least 2-3 named case studies with specific numbers and timeframes.
- [ ] At least 2 objections explicitly handled in the visitor's own words ("you might be thinking..." / "now I know what you're going to say...").
- [ ] Offer reveal is unambiguous — price stated or scoped, deliverables itemized.
- [ ] Risk reversal is specific (not "we have a money-back guarantee" but "if you don't [outcome] in [timeframe], you don't pay").
- [ ] Scarcity is REAL — cohort start date, hard seat cap, calendar limit. No fake countdowns.
- [ ] Closes with two-paths framing OR every-day-you-wait cost framing OR direct "click below right now".
- [ ] Voice passes the read-out-loud test. No staccato. Oxford commas in lists. Transitions feel like someone actually talking.
- [ ] Length matches the matrix above (±15%).
- [ ] No throat-clearing openings ("In this video I'm going to..."). No throat-clearing closings ("Thanks for watching!").

## Output format

Default output: a single markdown file with:

1. **Meta block** — offer, tribe, target length, traffic source
2. **Beat outline table** — 11 rows with the headline of each beat and a time budget
3. **Full script** — the spoken lines, broken into beat sections with `## Beat N — {beat name} [MM:SS]` headers
4. **Pacing markers inline** — `[pause]`, `[hold beat]`, `[smile here]`, `[hit harder]` in italics
5. **Director's notes** at the end — what to wear, what's on screen, where to cut

Save as `vsl-script-{slug}.md` in the project or workspace folder. If working inside a landing-page project, save to `workspace/{project}/vsl-script.md`.

## Anti-patterns (never ship these)

- "Hi everyone, my name is [name] and today I want to talk to you about..." → throat-clearing
- "If you're like most people..." → generic, signals nothing
- "I want to share with you a unique system..." → "unique" is doing zero work
- Three+ short sentences in a row separated by periods (the AI-staccato pattern)
- Generic results ("transformed his business", "got amazing outcomes") — replace with specific numbers every single time
- "Limited time only!" with no actual deadline — destroys trust
- A "thanks for watching" or "I hope this was helpful" close — closes never thank, they CTA
- A discount-only close ("save 30% if you buy today") — discount is the weakest closer; outcome + risk-reversal + scarcity is stronger
- Reading the offer like a feature list with no value-anchors ("you get 6 modules and 4 bonuses") → frame each piece as a problem it solves
